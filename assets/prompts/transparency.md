# 透明背景の作りかた（fal-ai/flux/dev むけ）

## なぜ後処理が要るのか

**fal-ai/flux/dev には透明背景を出す機能がありません。**

`transparent background` とプロンプトに書いても透明にはなりません。
返ってくるのは、灰色の面や、市松模様を「絵として描いた」画像です。
市松模様を描かれると、かえって抜けなくなります。

だから、この方式は使いません。

```
✗ プロンプトに transparent background と書いて祈る
○ 抜きやすい単色の下地を描かせて、機械で抜く
```

## 流れ

```
Fal FLUX 生成（output_format=png）
   ↓
PNG 取得
   ↓  npm run assets:remove-background
背景除去（端からつながる下地だけを抜く）
   ↓
アルファチャンネル生成（透け具合を実測）
   ↓
白/灰色/単色の残留ピクセル除去（ハロー除去）
   ↓
半透明ハロー除去（スピル除去 + 薄い膜の切り落とし）
   ↓  npm run assets:normalize
人物領域の bounding box 検出
   ↓
1024×1280 の基準キャンバスへ正規化配置
   ↓
透明PNGとして保存
   ↓  npm run assets:validate
品質検査（14項目）
   ↓  npm run assets:manifest
manifest 登録
   ↓
ゲームへ同梱
```

**ここから先はすべて開発時の処理です。ゲーム実行時には1行も動きません。**

## 下地の色

`#00B140`（鮮やかな緑）を使います。`MATTE_BACKGROUND` で定義しています。

なぜ緑か：

| 色 | 肌 | 髪 | 生成りの白 | 判定 |
| --- | --- | --- | --- | --- |
| 白 `#FFFFFF` | 近い | 遠い | **ほぼ同じ** | ✗ ユニフォームまで抜ける |
| 灰 `#808080` | 近い | 近い | 近い | ✗ 陰影まで抜ける |
| 緑 `#00B140` | 遠い | 遠い | 遠い | ○ |

もうひとつ大事なのは、**鮮やかな色なら透け具合を正確に測れる**ことです。

輪郭の画素は「人物の色 × a + 下地の色 × (1−a)」で描かれています。
緑の下地なら「緑が赤と青をどれだけ上回っているか」から a を逆算できます。
白や灰色ではこれができず、色の差から見立てるしかないので、縁が甘くなります。

## ハローが出る理由と、その消しかた

生成器は輪郭をなめらかに描くので、人物と下地が混ざった画素が必ずできます。
これをそのまま抜くと、**緑や白の縁取り**が残ります。

3段構えで消しています。

1. **引き算（defringe）**
   観測色から下地のぶんを引いて、人物そのものの色を取り戻す
   `元の色 = (観測色 − 下地 × (1−a)) ÷ a`

2. **スピル除去（despill）**
   それでも下地の色が突出している画素は、他の2成分の平均まで抑える

3. **薄い膜の切り落とし（trimHalo）**
   アルファが 40 未満の画素は落とす

実測：緑の下地で作った画像を通すと、
縁に残る緑は **78% → 0.0%** になります（人物の色は変わりません）。

## 検査（14項目）

`npm run assets:validate` が1枚ずつ見ます。**FAIL が1件でもあれば production に入れません。**

| 項目 | 落とすもの |
| --- | --- |
| PNGである | JPEG などで生成した素材 |
| 壊れたPNGではない | 途中で切れたファイル |
| alpha channelが存在する | 背景を抜いていない素材 |
| 四隅が透明 | 抜き漏れ |
| 背景色が残っていない | 画面のほとんどが不透明 |
| 白い縁取りがない | 白い下地の消し残り |
| 灰色の縁取りがない | 灰色の下地の消し残り |
| 半透明の背景ハローがない | うっすら残った膜 |
| 人物がキャンバス外にはみ出していない | 見切れ |
| bounding boxが極端に小さくない | 人物が小さすぎる |
| bounding boxが極端に大きくない | 抜けていない／大きすぎる |
| 基準点が仕様どおり | 位置ずれ |
| 1024×1280 | 大きさ違い |
| ファイルサイズ上限以内 | 1465 KB 超 |

### 白髪を誤って弾かないために

「縁が白い」だけで落とすと、**白髪の素材や白いユニフォームまで落ちます**。

消し残りは「**縁だけ**が内側より明るい」。白髪は「縁も内側も白い」。
そこで、縁と内側の明るさの差（`lift`）で見分けています。

## ネットワークの許可（Claude Code on the web で動かすとき）

生成を実行する環境が外部へ出られないと、鍵が正しくても 403 で止まります。

```
fal が 403 を返しました: Host not in allowlist: fal.run.
Add this host to your network egress settings to allow access.
```

これは**鍵の問題ではなく、実行環境の通信設定**です。
環境の egress 許可リストに、次のホストを足してください。

| ホスト | 用途 |
| --- | --- |
| `fal.run` | 生成を頼む先 |
| `queue.fal.run` | 待ち行列を使うモデルのとき |
| `fal.media` / `v3.fal.media` | 出来上がった画像の置き場所 |

許可リストは、環境を作るときに選ぶネットワーク方針で決まります
（https://code.claude.com/docs/en/claude-code-on-the-web）。

**通信を開けられないときは、`IMAGE_PROVIDER=local` を使ってください。**
手元（ブラウザなど）で作った PNG を `assets/incoming/<素材ID>.png` へ置けば、
背景除去から先はまったく同じ流れで動きます。文面は
`npm run assets:prompts` が `assets/prompts/generated-prompts.md` に書き出します。

## モデルの選びかた（fal で試した結果）

fal は1つの窓口で色々なモデルを扱えます。`IMAGE_MODEL` を変えるだけで切り替わり、
受け付ける形（画像サイズの書き方・文字数の上限・透明背景の可否）は
つなぎの側が吸収します。

実際に同じお題（「顔の造作を一切描かない頭の形」）で試した結果：

| モデル | 指示の読み取り | 背景 | 抜いた結果 |
| --- | --- | --- | --- |
| `fal-ai/flux/dev` | 弱い。写実的な顔を丸ごと描く | 緑（やや淡い） | 抜ける（白縁0%） |
| `fal-ai/flux-pro/v1.1` | 強い。線画・禿頭になる | **白**（緑の指示を無視） | **抜けない**（白縁53%） |
| `fal-ai/gpt-image-1/text-to-image` | 強い（評価中） | **透明をそのまま出せる** | 抜く必要なし |
| `fal-ai/recraft-v3` | 線画が得意（評価中） | 単色 | プロンプト1000字まで |

分かったこと：

- **背景が白だと抜けません。** 肌もユニフォームも明るいので、区別がつきません。
  flux-pro は絵は良いのに、白い下地を描くせいで使えませんでした。
- **透明背景をそのまま出せるモデルがいちばん確実です。**
  GPT Image は `background: transparent` を受け付けるので、抜く工程が丸ごと要りません。

### GPT Image を使うとき

```
IMAGE_MODEL=fal-ai/gpt-image-1/text-to-image
```

- 画像サイズは決まった文字列のみ（`1024x1536` が縦長）。正規化で 1024x1280 に直します
- 透明背景をそのまま出すので、`assets:remove-background` は「不要」と判断して素通しします
- 配信ホスト（`v3b.fal.media`）から画像を取ってくるので、閉じた環境では
  そのホストを許可リストに入れる必要があります（`sync_mode` が使えないため）

## いきなり量産しない

```sh
npm run assets:generate -- --dry-run          # API を呼ばずに予定枚数だけ見る
npm run assets:generate -- --type head_shape,hair_style,eyes --count 1
npm run assets:remove-background
npm run assets:normalize
npm run assets:compare                        # 元 → 除去後 → 正規化後 を見比べる
npm run assets:validate
```

`assets-compare.html` をブラウザで開き、**市松模様の下地が透けて見えること**を
目で確かめてください。ここが確認できるまで量産しないでください。

10枚を超える生成には `--confirm-large-batch` が要ります。

## うまく抜けないとき

| 症状 | 原因 | 直しかた |
| --- | --- | --- |
| 「下地が一様ではありません」と出る | 背景に模様・陰影が描かれた | プロンプトの背景指定を強める。`--type` を絞って作り直す |
| 抜いたら何も残らない | 下地と人物の色が近すぎる | 下地の色を変える（`MATTE_BACKGROUND`） |
| 緑の縁が残る | スピルが強い | `--inner` を上げる（既定 26） |
| 人物が削れる | 抜きすぎ | `--outer` を上げる（既定 76） |
| 髪の細いところが消える | 薄い膜の切り落としが強い | `trimHalo` のしきい値を下げる |
