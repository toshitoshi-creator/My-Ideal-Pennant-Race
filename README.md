# My Ideal Pennant Race — PHASE 3.2

プレイヤーが**プロ野球球団の監督兼GM**となり、選手を直接操作せず、**選手編成と采配**でチームを勝利へ導く球団経営シミュレーション。

このリポジトリは **PHASE 1（実際に遊べる最小完成版）** に、
**PHASE 2（選手の個性と成長）**、**PHASE 2.5（調子の実効能力への反映）**、
**PHASE 3.1（引退・ドラフト・世代交代）**、**PHASE 3.2（スカウト）** を追加したものです。

> **PHASE 1 の目的**は「見た目が完成すること」ではなく、
> 球団を選ぶ → 選手を見る → 1軍を編成する → 打順を決める → 試合をする → 勝敗が決まる →
> 成績が変わる → 順位が変わる → 日付が進む → セーブされる
> という一連のゲームループが**完全に動作すること**です。

## スマートフォンで遊ぶ

### A. 1枚のHTMLファイルにして持ち歩く（いちばん手軽）

```bash
npm run build:single      # dist/my-ideal-pennant-race.html が出来る
```

出力された HTML は JS も CSS も内蔵した**完全に自己完結した1ファイル**です。
AirDrop・クラウドストレージ・メール添付などでスマートフォンに送り、ブラウザで開けばそのまま遊べます。
Safari の「共有 → ホーム画面に追加」/ Chrome の「ホーム画面に追加」をしておくと、
アドレスバーのないフルスクリーンでアプリのように起動できます。

### B. 同じ Wi-Fi のPCから開発サーバーを開く

```bash
npm run dev -- --host     # 表示された Network: http://192.168.x.x:5173/ をスマホで開く
```

PC とスマートフォンを同じ Wi-Fi につないでおく必要があります。コードを直すとその場で反映されます。

### C. 静的ホスティングに置く

`npm run build` の出力（`dist/`）はどこに置いても動く静的ファイルです（相対パス出力）。
GitHub Pages / Netlify / Vercel などにそのまま配置できます。

> **セーブデータについて**
> セーブは開いたブラウザの localStorage に保存されます。
> PCとスマートフォン、あるいは別のブラウザの間でセーブデータは共有されません。
> シークレットモードやサイトデータの削除でも消えるのでご注意ください。

## PHASE 2：選手の個性と成長

18歳のGランク選手が2軍で育ち、1軍に上がり、主力になり、30代で衰えていく——
そんな選手一人ひとりの物語が自然に生まれるようにするのが PHASE 2 の目的です。

| 要素 | 内容 | 実装 |
| --- | --- | --- |
| 年齢 | シーズン終了時に1歳加算。18〜38歳 | `domain/season.ts` |
| 潜在能力 | 1〜100。**数値は表示せず**「将来性：非常に高い〜非常に低い」で表示 | `domain/growth.ts` |
| 成長タイプ | 早熟 / 普通 / 晩成 / 超晩成 / 天才型 / 安定型 / 波瀾型 | `domain/growth.ts` |
| 成長 | 年齢・成長タイプ・性格・潜在能力・出場経験・成績・モチベーションの積で決まる | `domain/growth.ts` |
| 衰退 | 31歳以降。走力・球速は早く、制球・守備・捕球は緩やかに落ちる | `domain/growth.ts` |
| 性格 | 努力家・天才肌・負けず嫌い・冷静・リーダー・ムードメーカー・繊細・マイペース・野心家・職人気質 の10種 | `domain/personality.ts` |

| コンディション | 絶好調〜絶不調の5段階。能力カテゴリごとに効き方が違う（PHASE 2.5） | `domain/condition.ts` |
| モチベーション | 出場機会・活躍・勝敗で変動。成長量と実効能力に影響 | `domain/condition.ts` |
| 怪我 | 軽傷（数日）/ 中傷（数週間）/ 重傷（数ヶ月）。疲労が高いほど発生しやすい | `domain/injury.ts` |
| スランプ | 不振が続くと一時的に実効能力が低下。時間経過・好調で回復 | `domain/condition.ts` |
| 覚醒 | 若手・高潜在・高モチベーション・一定以上の出場で低確率発生 | `domain/growth.ts` |

### 基本能力と実効能力を分ける

パワー70の選手の**基本能力は70のまま**です。疲労や不調の影響は毎試合
「実効能力」として計算され、選手本来の力と当日の調子を区別しています。

```
実効能力 = 基本能力 × clamp(1 + 疲労 + モチベーション + スランプ + チーム士気 + 性格
                              + 調子（能力カテゴリ別）, 0.72, 1.16)
```

掛け算が積み重なって極端にならないよう、最終倍率は **0.72〜1.16 倍**に制限しています
（`domain/effective.ts`）。特殊能力は能力値ではなく**イベント発生率への係数**として働き、
効果キーごとに上限を設けています（`domain/specialAbilities.ts`）。

## PHASE 2.5：調子（コンディション）

「調子が良い＝全能力◯倍」にはせず、**能力カテゴリごとに効き方を変えて**います。

| 調子 | ミート系 | パワー系 | 走力系 | 守備系 | 球威系 | 制球系 | 変化球系 | スタミナ系 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 絶好調 | +6% | +5% | +4% | +4% | +5% | +4% | +4% | +3% |
| 好調 | +3% | +2% | +2% | +2% | +3% | +2% | +2% | +1% |
| 普通 | ±0% | ±0% | ±0% | ±0% | ±0% | ±0% | ±0% | ±0% |
| 不調 | -3% | -2% | -2% | -2% | -3% | -2% | -2% | -1% |
| 絶不調 | -6% | -5% | -4% | -4% | -5% | -4% | -4% | -3% |

弾道は打球の性質なので調子では変わりません。

### 調子の変化（隣接遷移）

調子は毎日更新されますが、**1段階ずつしか動きにくい**マルコフ連鎖になっています
（絶不調からいきなり絶好調へは飛びません。2段階以上の移動は全変化の15%未満）。
移りやすさは「その段階の出やすさ × 現在からの距離 × 疲労・モチベーション・士気によるバイアス」で決まり、
乱数は呼び出し側から渡すのでシードを固定すれば再現できます。

疲労が高いと好調になりにくくなりますが、**疲労が高い＝必ず不調ではありません**。

### 性格との相互作用

| 性格 | 調子まわりの効果 |
| --- | --- |
| 努力家 | 不調の低下を **-20%**、絶不調の低下を **-15%** 軽減 |
| 繊細 | 調子の振れ幅が **1.45倍**（好調の上振れも不調の下振れも大きい） |
| 冷静 | 調子の振れ幅が **0.85倍** |
| 職人気質 | 調子の振れ幅が **0.85倍**（波が小さい） |
| マイペース | 調子の振れ幅が **0.6倍**、疲労の影響も **0.6倍** |
| ムードメーカー | チーム士気の影響を **1.5倍**受ける |

### 特殊能力との相互作用

特殊能力は能力値に加算せず、既存どおりイベント発生率への係数として働きます。
調子はその係数の「1からのズレ」を拡大・縮小します（絶好調 ×1.12 / 絶不調 ×0.88）。
好調なら長所が出やすく短所が出にくく、不調ならその逆になります。
効果キーごとの上限は変わらず最後に適用されます。

### 調子の検証結果（143試合 × 10シーズン = 8,580試合）

| 調子 | 出現率 | 打率 | 本塁打率 | 防御率 | 奪三振率 |
| --- | --- | --- | --- | --- | --- |
| 絶好調 | 7.3% | .273 | 2.44% | 3.74 | 7.70 |
| 好調 | 16.5% | .268 | 2.32% | 3.89 | 7.56 |
| 普通 | 33.3% | .262 | 2.30% | 4.04 | 7.30 |
| 不調 | 25.6% | .254 | 2.24% | 4.30 | 6.97 |
| 絶不調 | 17.2% | .252 | 2.11% | 4.60 | 6.83 |

* **打線の調子が良い側の勝率は .515** — 調子だけで勝敗が決まることはありません。
* 実効能力倍率の実測値は **0.753〜1.109**（平均 0.991）で、制限の 0.72〜1.16 の内側に収まります。
* 1シーズン目の出現率は 絶好調8.3% / 好調18.9% / 普通32.6% / 不調24.9% / 絶不調15.4% と目標分布どおりです。

### 怪我と7日ルール

怪我をした選手は自動的に1軍から外れ、オーダー・ローテーションからも除外されます。
**怪我による抹消は7日間の登録変更制限の例外**で、復帰後はすぐ再登録できます。
怪我人が増えて1軍の野手が9人・投手が5人を割りそうなときは、2軍から自動で繰り上げます。

### バランス確認（10シーズン自動シミュレーション）

`npx vite-node scripts/balance.ts 10` の結果（143試合 × 10年）：

* 全選手の平均総合 **37.5 → 38.5**（能力インフレなし）
* 総合ランクは G〜A に分散（全員が同じ能力にはならない）
* 22歳以下は平均 **+2.4**、33歳以上は平均 **-0.6**（若手は伸び、ベテランは衰える）
* 怪我は **1球団あたり年 4〜6件**、1試合あたりの発生率は 5% 未満
* 1軍選手の平均疲労 **17〜22**、コンディションは 絶好調8% / 好調19% / 普通32% / 不調25% / 絶不調15%
* 特殊能力の有無による勝率差は **+2.5ポイント**（`scripts/ab-special.ts` で A/B 計測）

> ※ この高齢化の問題は PHASE 3.1 のドラフト・引退システムで解消済みです（下記参照）。

## PHASE 3.1：引退・ドラフト・世代交代

選手が成長し、ベテランになり、衰え、引退し、新人が入ってきて次世代の主力になる——
という循環を完成させました。

```
シーズン終了 → 年齢+1・成長／衰退 → 引退判定 → ドラフト候補生成 → ドラフト会議
→ 新人加入（2軍スタート） → ロスター再構築 → 翌シーズン開幕
```

年齢の加算は成長処理の中の1回だけで、引退・ドラフトでは加算しません。
同じシーズンで2回ドラフトが起きないよう `lastDraftYear` で冪等性を担保しています。

### 引退（`domain/retirement.ts`）

年齢を最重要要素とした確率判定です。25歳以下は0%、33歳で3%、35歳で12%、
38歳で50%、41歳以上で95%を基準に、次の補正がかかります。

* **能力**：総合が高いほど残りやすい（±35%まで）。ただし高能力でも40代の引退率は高い
* **出場機会**：出番のないベテランは最大+35%
* **怪我**：長期離脱中は+25%（怪我だけで即引退にはならない）

引退した選手はロスター・オーダー・ローテーションから外れ、
名前・球団・年齢・通算年数・最終総合が `retiredPlayers` に記録されます（将来の殿堂用）。

### ドラフト（`domain/draft.ts`）

* **候補**：毎年 12球団 × 9人 = **108人**。年ごとに「当たり年・不作年」の差が少しつきます
* **新人**：18〜22歳（高卒18歳が中心）。既存の `createPlayer()` をそのまま使うので、
  性格・成長タイプ・潜在能力・特殊能力・調子・モチベーションはすべて通常の選手と同じ仕組みです
* **指名順**：前年成績の悪い球団から。同率はシード乱数で決定
* **巡数**：各球団の不足人数（目標25人）から決まり、最大6巡。埋まった球団はパス
* **CPU評価**：`現在能力×0.50 + 潜在能力×0.30 + ポジション不足×0.15 + 適性×0.05`（+わずかな揺らぎ）

**潜在能力の実数値はUIに表示しません。** 候補カードには「将来性：非常に高い〜非常に低い」の
ラベルだけを出し、`projectedPotential` として保持しています。
PHASE 3.2 でスカウト精度（`scoutedPotentialLabel`）を差し込めるよう、
「内部の真の潜在能力」と「プレイヤーに見える情報」を分離してあります。

### 世代交代の検証（143試合 × 20シーズン）

| | 開始 | 5年目 | 10年目 | 15年目 | 20年目 |
| --- | --- | --- | --- | --- | --- |
| 平均年齢 | 26.3 | 28.0 | 28.1 | 27.4 | 27.7 |
| 平均総合 | 37.5 | 41.0 | 41.4 | 40.9 | 39.9 |
| 22歳以下 | 84人 | 34人 | 63人 | 65人 | 48人 |
| ロスター | 25人 | 25人 | 25人 | 25人 | 25人 |

* **平均引退年齢 36.5歳 / 年間 約17人が引退し、同数の新人が加入**
* 平均年齢は26〜28歳で安定（PHASE 2.5 では10年で36歳まで高齢化していました）
* リーグ平均総合は40前後で頭打ちになり、青天井のインフレは起きません
* 最高総合も65〜71で、初期（67）と同水準

## PHASE 3.2：スカウト

ドラフトを「一覧から強い選手を選ぶだけ」ではなく、
**限られた情報から将来活躍する選手を見抜く**意思決定にしました。

### 真のデータと、見えている情報を分ける

```
Player（真のデータ）          ScoutReport（球団が調査で得た推定）
├ 基本能力                    ├ 推定現在能力（幅のある評価）
├ 潜在能力                    ├ 推定将来性（5段階ラベル）
├ 性格                        ├ 推定性格（「努力家？」など）
├ 成長タイプ                  ├ 推定成長タイプ（「晩成傾向」など）
└ 特殊能力                    ├ 発見済みの素質・弱点
                              └ 項目ごとの調査進行度と信頼度
```

ScoutReport は **Player の真の値を一切書き換えません**。
UIに出るのはすべて ScoutReport の推定情報で、潜在能力の実数値は表示されません。

### スカウト能力（球団ごと）

| 項目 | 影響 |
| --- | --- |
| 能力の見極め | 現在能力の推定誤差と評価幅 |
| 将来性の見極め | 将来性ラベルの正確さ（既存の `scoutedPotentialLabel()` を使用） |
| 人物調査 | 性格・成長タイプの正確さ |
| 素質の発見 | 特殊能力の発見率と、名前・Lvが分かるまでの深さ |

情報精度は `0.18 + (0.25 + 能力/100 × 0.45) × 調査進行度 × 1.18`（上限0.97）で、
**スカウト能力と調査進行度の両方**で決まります。
能力が低い球団は100%調査しても完全には見抜けません。

### 調査ポイント（年60ポイント）

| 調査 | コスト | 1回の進行 |
| --- | --- | --- |
| 現在能力 | 2pt | +34% |
| 将来性 | 4pt | +34% |
| 性格・成長タイプ | 3pt | +34% |
| 特殊能力 | 4pt | +34% |

* 1人を全項目100%まで：39pt → **1.5人**
* 現在能力＋将来性を1段階ずつ：6pt → **10人**
* 現在能力だけ1段階：2pt → **30人**

「誰を重点的に調べるか」を選ぶ設計です。候補108人を全員調べることはできません。

### 情報精度の実測（候補120人・`scripts/scouting-balance.ts`）

| スカウト | 進行度 | 現在能力の平均誤差 | 評価幅 | 将来性の正解率 | 信頼度 |

**マイナス特殊能力はプラスより見つけにくく**（浅い調査ではほぼ見えない）、
隠れた弱点を見抜くこと自体がスカウトの価値になります。

### 情報は「調べた時点で確定」する

推定は調査したときに確定して保存されるので、画面を開き直すたびに評価が変わることはありません。
調査を進めると誤差が縮んで真値へ**収束**します（別の値へ飛びません）。
球団ごとに ScoutReport とポイントは完全に独立していて、他球団の調査結果は見えません。

### CPUのスカウト

CPU球団も自分のスカウト能力とポイントの範囲で調査し、
**その推定値で**指名します（真の潜在能力は参照しません）。
下馬評の上位から、2人を深く・6人を中程度・12人を浅く調べる配分です。
未調査の候補は公開情報だけで評価されるため、CPUも見落としをします。

### 試合シミュレーション

完全ランダムではなく、**打席ごと**に打者能力と投手能力・守備力から結果を決めます。

* 投手力：球速・制球・スタミナ・球威・変化量（スタミナが切れると能力が低下し、救援に交代）
* 打撃力：ミート・パワー（弾道は加算せず、独立した係数として長打・本塁打率に作用）
* 守備力：守備・捕球・肩（**本職と違う守備位置ではペナルティ**が入り、失策率も上がる）
* 四球 → 三振 → 本塁打 → 失策 → 安打（単打/二塁打/三塁打）→ 凡打（ゴロ/フライ/併殺/犠飛）の順で判定
* 盗塁は走者の走力と捕手の肩で成否が決まる
* 9回裏でホームがリードしていれば裏の攻撃なし。同点なら延長12回まで、決着しなければ引き分け

チーム能力が高いほど勝率は上がりますが 100% にはなりません（ゲーム内で起こりうる最大の戦力差でおよそ 6〜7 割）。

### 弾道について

弾道も他の基本能力と同じ **1〜100（G〜Aランク）** で扱います。
ただし弾道は他の能力とは意味が異なるため、**試合計算では他能力と同じ割合で加算しません**。
`domain/trajectory.ts` に独立した係数として切り出し、MatchEngine（`domain/simulation.ts`）は
この係数を通してのみ弾道を参照します。

| 係数 | 用途 | 弾道25 | 弾道50 | 弾道75 | 弾道100 |
| --- | --- | --- | --- | --- | --- |
| `homeRunFactor()` | 本塁打発生率に乗算 | 0.55 | 0.85 | 1.15 | 1.45 |
| `extraBaseFactor()` | 二塁打の出やすさに乗算 | 0.875 | 1.00 | 1.125 | 1.25 |
| `groundBallRate()` | 打球のゴロ率 | 0.65 | 0.56 | 0.47 | 0.38 |

旧仕様（1〜4の4段階）のセーブデータは読み込み時に **1→25 / 2→50 / 3→75 / 4→100** へ自動移行します
（`domain/save.ts` の `migrate()`、セーブスキーマ v1 → v2）。

## セーブデータの互換性

セーブデータは `version` を持ち、`domain/migrate.ts` が古いデータを変換します。

| version | 内容 | 移行処理 |
| --- | --- | --- |
| v1 | PHASE 1（弾道 1〜4） | 弾道を 1→25 / 2→50 / 3→75 / 4→100 に変換 |
| v2 | 弾道 1〜100 | PHASE 2 のデータ（性格・潜在能力・成長タイプ・特殊能力・状態）を安全な初期値で補完 |
| v3 | PHASE 2 | 調子の履歴などPHASE 2.5のフィールドを補完 |
| v4 | PHASE 2.5 | 引退記録・ドラフトのフィールドを補完 |
| v5 | PHASE 3.1 | スカウト能力・調査ポイントを補完 |
| v6 | PHASE 3.2（現行） | － |

補完は選手IDから決まる乱数で行うため、同じセーブを読み直しても同じ結果になります。
既存の能力・成績・順位・日付・1軍/2軍・7日制限は一切書き換えません。
DH制は `League.useDH` で切り替わり、リーグごとに設定できます（オーシャンリーグがDH制）。
